# Release notes for the pre-1.0.0 line

Every note the app wrote before its versioning restarted, newest first as the
directory lists them: the 3.x line, 4.x, 5.x, 6.0.0 and the 7.0.0 work (whose
release was never published). They are kept as the record of what each of those
versions changed — the code, the tests and the spec still cite them by number
(for example the HDCD report that 4.5.0 fixed, or 4.8.0's "Unrecognized MEDIA
value" payload the tag index had to drop).

**1.0.0 is where the numbering starts again**, and its note lives one directory
up (`docs/release-notes/release-notes-1.0.0.md`) because the release workflow
reads `docs/release-notes/release-notes-<version>.md` for the tag being
published. Nothing here is deleted or superseded: an old release's own note is
the only place its reasons are written down.
