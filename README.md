# la musica
**v4.3.1** — a self-hosted app that *manages, optimizes, audits, grades and plays* your music library, from a browser, a desktop window or a phone.
**la musica** is a FastAPI backend plus a React UI over the `mlo` engine: music and music videos, playlists, likes and favourites, artist artwork and biographies, a multi-source lyrics chain and MusicBrainz/Discogs/AcoustID identity.
State — config, playlists, the beets library, Soulseek config, caches, runtime-installed tools — lives in one hidden `.mlo` folder beside your music; release notes are in `docs/release-notes/release-notes-<version>.md`. Contract: [`docs/OPTIMIZATION-GRADING-SPEC.md`](docs/OPTIMIZATION-GRADING-SPEC.md).
## Quick start
### Docker (recommended)
```bash
docker compose up -d --build     # build from source and start
docker compose logs -f           # follow the backend log
docker compose pull              # fetch the prebuilt GHCR image instead
docker compose down              # stop and remove
# open http://localhost:8000 — your library is mounted at /music
```
- **Edit one line first**: Docker is the only supported **server** install; the bind mount committed as `./music:/music` must become an absolute host path (`/path/to/music:/music`, `D:/Music:/music`).
- Image `ghcr.io/dillydalli3r/la-musica:latest`, container `la-musica`, port `8000`; `MLO_MUSIC_FOLDER=/music` is the only env var it needs, and `MLO_SERVER_HOST=0.0.0.0` makes the published port reachable and turns the login gate on.
- `/music` holds the library **and** all app state (`data`, `downloads`, `trash`, tools) and unprivileged `mlo` is uid/gid **1000**, so the mount must be writable by uid 1000 or `.mlo` cannot be created; healthcheck `http://127.0.0.1:8000/api/health`, 30 s; `watchtower` (`WATCHTOWER_POLL_INTERVAL`, 300 s) replaces a `--build` image with the published one, so to keep building from source start only the app: `docker compose up -d lamusica`.
### From source
```bash
python -m pip install -r server/requirements.txt
python -m uvicorn server.main:app --host 127.0.0.1 --port 8000
cd web && npm install && npm run dev   # dev: http://localhost:5173 proxies /api and /ws to :8000
cd web && npm run build                # production (tsc -b && vite build); the backend serves web/dist
python -m uvicorn server.main:app --host 127.0.0.1 --port 8000   # http://127.0.0.1:8000
```
- `python -m server.main` reads `server_host` / `server_port` from the config and binds there; the music folder is picked in the UI (**Settings → General → Music folder**) or `GET /api/fs/dirs`, and choosing one *moves* `<music>/.mlo` into it.
- Tools install from **Settings → Dependencies** (`ffmpeg`, `flac`, `libjxl`, `jpegtran`, `oxipng`, `rsgain`, `AudioAuditor`, `Logchecker`, `php`, `CUETools`, `fpcalc` optional, `librosa`, `beets`, `slskd`, `yt-dlp`; rows are `deps`, `unsupported` or `system`); `dependencies_auto_update` (on) installs missing tools on boot.

## What the app does
### Library, search and identity
- Artists → albums → tracks with live grade/audit badges, a *fail only* filter, bulk tag tools and custom tag columns; music videos are first-class tracks (a web/digital album can fetch its own through yt-dlp, gated by `youtube_enabled`); album badges carry dynamic range (`ADR`). Every track row's "…" menu comes from the script registry (`GET /api/script-menu`), and the search bar searches the library (`composer:`, `person:`, `genre:`, `tag:`) or MusicBrainz, with `/mb/search` as the MusicBrainz browser; entity pages carry MB/RYM links, cover search (`cover_review`), tag editing and a **Credits** view from `artist-rels`.
- **A badge says where the files came from, and an artist wears its own verdict**: a `Digital Media` album's badge is `Digital Media · Bandcamp · US` (medium · source · countries, from the release's own store links; the app's own `Digital` default repeats the medium and is dropped), and every place an artist's name is drawn — the artist page, the library's Artists view, Home's shelf, Favorites — carries a green dot when that artist passes its own checks (image + description), instead of chips spelling the checks out.
- **An alias is a name, not a footnote.** MusicBrainz aliases are imported as tags (`TITLEALIAS` / `ARTISTALIAS` / `ALBUMALIAS`, plus `…-<locale>` when MB states the language), the library SHOWS the alias with the original beside it (`宇多田ヒカル (Hikaru Utada)`), the search bar and the query builder match them, lyrics/advisory lookups ask the original name first and the alias second (LRCLIB is submitted under both), and a track written in a non-Latin script fails grading without one (`grade_check_alias_needed`).
- **LIBRARY → BROWSE** is a query builder over 120 fields whose saved form is a **smart playlist**; **Ratings** are half stars in the UI, Picard's 0–10 in the store, written to the file's `RATING` tag; **five views** (Grid, Compact, Albums, Artists, Tracks) each carry sort, columns, presets (*Failing*, *CD rips*, *Instrumental*, …).
- **Podcasts are a series, not an album** (`PODCASTSERIES`, `PODCASTSERIESMBID`, `PODCASTEPISODE` on the files; a **Podcasts** shelf on Home, `/podcast/<series>`, `GET /api/podcasts?series=…`); **Recommended (Local)** and **Home** use the library's own tags, and the accent colour is per device (15 presets, `#rgb`/`#rrggbb`, `localStorage["mlo.accent"]`).
### Discover, recommendations and watching
- **DISCOVER** browses genres across every configured provider (library/online/both); **RECOMMENDED (ONLINE)** seeds from the library, a genre or the current page and its **(LOCAL)** half from the library's own tags; **WATCHED ARTISTS** keeps an artist under watch (policy, release types, allow/never lists, a per-cycle cap).
### Player
- A persistent player bar (queue, drag-reorder, shuffle, repeat-one, speed, sleep timer, ReplayGain, visualizer, app-wide volume) plus a fullscreen player; a video is transcoded to fragmented MP4 when its codec needs it (`GET /api/videos/stream?transcode=1`). Lyrics come from the `.lrc` beside the file and/or its `LYRICS` tag, and a single track's own surfaces say **Synced** or **Plain** (`lyrics_kind`; `lyrics_allow_plain` ships off).
- **The cover arrives with the play press, not a second after it.** Every surface asks the server for the width it draws (`GET /api/cover?w=`, bucketed 160/320/640/1200, cached under `<music>/.mlo/data/cover_thumbs` keyed by the cover's own stat), the fullscreen picture and its ambient blur share one request, and the next track's cover rides along with the gapless preload — measured on a throttled link: 3.13 MB and two requests at ~1230 ms before, 12 KB, one request, ~98 ms now.
- **It remembers where you were, and it plays without a gap.** A reload brings back the queue, the track and the second it was on (paused, without counting a second play); `gapless_playback` (ON) hands the next sequential track to the idle audio element so it starts seamlessly; **Ctrl+Z / Cmd+Z** undoes the last jump — a mis-clicked seek, a ±10 s skip — with no button of its own. On iOS the lock screen gets a real position and scrubber (`mediaSession.setPositionState`) and the ±10 s skip buttons, which the app used to declare unsupported.
- **The queue can keep going past its last track.** `infinite_playback` (OFF, so nothing changes until you ask for it) appends a handful of the library's **similar** tracks — scored locally from the queue's own tags, so no provider is asked and playback cannot hang on one — as ORDINARY queue rows, before the last row ends: the idle element is already preloaded with the first of them, so the sound is handed over exactly like an album advance. Nothing already in the queue is ever added twice, the batch is bounded (`GET`/`POST /api/recommend/queue`), Shuffle still gets the seeds' similar set, Repeat one appends nothing, and an empty answer simply ends the queue as it always did.
- ReplayGain runs through the WebAudio gain stage in **track**, **album** or **off** mode (`replaygain_mode`, `replaygain_preamp_db`, ±24 dB; `replaygain_measure_missing` measures untagged files on the fly); the **Equalizer** (sidebar → MAINTAIN) applies an Equalizer APO / Peace profile to playback (`playback_eq_profile`, `""` = off). **iOS**: the shell owns the audio session (`desktop/src-tauri/src/ios_audio.rs`) and wires `MPRemoteCommandCenter.likeCommand` (`desktop/src-tauri/src/ios_like.rs`).
### Import
- **An archive imports like the folder it contains**: drag & drop uploads, a watched folder and staged `.mlo/downloads` or Soulseek paths run through one pipeline (`server/imports.py`); `.zip`, `.tar`, `.tar.gz`/`.tgz`, `.tar.bz2`/`.tbz2`, `.tar.xz`/`.txz`, `.7z` or `.rar` is unpacked into staging (`POST /api/import/unpack`, discarded with `…/unpack/discard`). `SOURCE` comes from the release's store links or the provider the files came from, and when nothing states it the **Match** step asks once (`POST /api/import/source`, `digital_media_source_value`, shipped `Digital`). **AcoustID matching** identifies the release from the audio (`acoustid_api_key`, `fpcalc`) and writes `ACOUSTID_ID` + `ACOUSTID_FINGERPRINT`; **script 21** completes or creates that pair from the file itself, and **script 22** submits it (`acoustid_user_key`).
- **A single song out of a rip is imported into the album that rip is** (the album the library holds for that release id, else the file's `ALBUM` tag), MOVED in without overwriting anything, its `.cue`/`.log` TOC becoming the folder's `.mlo_expected.json` so the album reads as *partial*. **A streaming playlist** (Deezer, Spotify, YouTube Music, Apple Music) is read by URL (`POST /api/playlists/import/streaming`) and matched track by track (*Check* uses `dry_run`): `playlist_import_parent_albums` (off) queues unmatched tracks' parents, `playlist_import_unmatched` (`skip`/`wish`) queues the tracks, `playlist_import_create_empty` (on) keeps an empty result.
- The wizard's eight steps: **Select & separate → Links → Match → Covers → Genres → Lyrics → Advisory → Finish**; the **import script chain** (`import_scripts`, i.e. `DEFAULT_CHAIN` = `run_all_order`, one list in `mlo/config.py`) runs after the wizard (`import_auto_scripts` turns it off), families in `import_review_families` are left as they arrived, `import_autonomy` ships `automatic`, **bulk import** runs `import_bulk_concurrency` (2, 1–8), **Genres** asks the chain in `genre_sources` order and **Advisory** resolves `ITUNESADVISORY` with `advisory_ai_classify`. A framework album's cover is a stand-in until the real one is written; when the picked edition is not on the network the ranked editions are tried up to `soulseek_fallback_candidates` (1–10, 5 default); a wish takes only a lossless copy (`soulseek_auto_lossy_policy`, `never`).
### Soulseek & the download queue
- A managed slskd instance (autostart, shares = `<music>/Artists`) pushes transfer progress instead of polling (`GET /api/soulseek/downloads` and every live job ride the progress WebSocket as `{"type":"transfers"}` frames). **Is the port open?** *Test port* (`GET /api/soulseek/port-check`) answers with seven rows (TCP connect, bind, the published port, the gateway mapping, the LAN/WAN shape, a self-connect, the account's published address, slskd's state).
- The listen port is opened on the router by the app (`soulseek_upnp`, ON — UPnP IGD first, NAT-PMP behind it); from inside a container that request never leaves Docker's bridge, so name the router in **Router IP for port mapping** (`soulseek_router_ip`, blank = auto-detect) or forward by hand.
- **Which edition is fetched** is `mlo/release_choice.py`: official editions first, then `auto_import_medium_order` (shipped **CD, Vinyl, Cassette, Other, DVD, Blu-ray, VHS, Video CD, LaserDisc, Digital Media**), then the earliest date; disc streams are preferred (`prefer_disc_streams`), a release whose tracklist only completes with a music video is never preferred over an audio-only one, and a release you already hold is refused rather than becoming `… (2)`. The auto-importer searches by catalog number and barcode (`soulseek_auto_physical_queries`), else label and country, digital by `soulseek_auto_digital_queries`, and by MBIDs (`soulseek_auto_mbid_queries`, on, with `soulseek_auto_mbid_tracks`, 4); a CD candidate's `.log` is gated before any byte is requested (`soulseek_auto_log_min_score`, 100), and up to `soulseek_candidate_slots` (3) candidates and `soulseek_search_concurrency` (3) releases run at once (slskd's own `soulseek_download_slots` is never touched).
- A queued download imports itself once the WHOLE intended file set has arrived; `wishes_interval_hours` (1) spaces two attempts of a wish, and a retryable failure waits in the queue's **Background** section; the downloaded copy is deleted once its import lands (`soulseek_clear_downloads`, ON), and finished rows leave the queue's **Completed** section by themselves when the next import starts (`soulseek_clear_completed_on_import`, ON); **notifications only fire where the work really ended** — a finished download and the end of a whole import, never a download that is still being moved or verified, never one album of a bulk run — and they name the album, not its folder. with `import_autonomy` in review or `manual_import_enabled` off, the album is left in the download folder. **The search is two-phase**: a short first pass (`soulseek_search_fast_seconds`, 5 s) ends a quiet release's search so its results become readable in seconds and a complete lossless folder is enqueued the moment it is found; only when that finds nothing usable is the configured `soulseek_search_timeout_seconds` spent as the top-up window, and other releases keep searching while a transfer runs. **Cancel** drops the job's slskd searches and transfers and aborts at a safe point; **Clear all** empties queued work; two 5 GB caps hold (`soulseek_cache_cap_gb`, `trash_cap_gb`, 0 = off), never over a file in use (`server/job_locks`).
### Soulseek in Docker: the three links that have to line up
Sharing is not the web UI: another user reaches your files by opening a connection **back** to the listen port (default 50000, `soulseek_listen_port`) — **TCP only, no UDP and no second (obfuscated) port** — and that port must survive three hops. The sharing card carries this as a collapsed guide, with the host-firewall command for the listen port.

1. **The container publishes it.** `docker-compose.yml` publishes `${MLO_SOULSEEK_LISTEN_PORT:-50000}` on both sides; a missing or wrong line is the audit's `listen_unpublished`, naming the `ports:` line and the pin.
2. **The router forwards it to the HOST.** A router cannot forward to a container address — 172.18.0.x is Docker's bridge on the host and nothing on your LAN can dial it — so the forward names the **HOST's** LAN address, and the publish line carries the port in.
3. **The HOST's traffic actually leaves by the ISP line.** A peer's *Browse* is a connection BACK to the address the Soulseek server learned from your **login connection**, so a VPN or Tailscale exit node on the host makes it unforwardable however green everything else reads: compare your egress (`curl https://api.ipify.org`) with the router's WAN address and split-route the host while sharing; bare-metal installs get this measured in *Test port* → *Addresses*.

**A client on YOUR OWN network cannot prove any of it**: a same-LAN client is handed your public address and dials it from *inside*, and a router without NAT hairpinning refuses exactly that while the port is open to everyone else — test from another network.
### Optimization — the 22 scripts
Optimization → *Run All* executes `run_all_order`, shipped as **11 → 3 → 14 → 15 → 2 → 1 → 13 → 18 → 17 → 8 → 5 → 19 → 6 → 7 → 9 → 12 → 16 → 10 → 20 → 21 → 4**; every script also runs on its own, a script that moves an album takes its claim with it (`server.job_locks.move`), and **22 (Submit fingerprints) is opt-in** (it publishes to AcoustID's public database) so it is not in the shipped order (`server.script_runners.OPT_IN_SCRIPTS`).

| 9 | AccurateRip | CUETools `.accurip` generation and verification, regenerated only when a track's audio changed |

**What script 17 transliterates is decided from evidence** (`mlo/lyrics_xlit.xlit_needs`): the track's `LANGUAGE` tag, then the script of its lyrics, then the function words of the languages the app knows; **script 6** keeps an evidence record per file (size, mtime and FLAC's STREAMINFO MD5), so an unchanged album is not re-audited.
Force flags, one per script (`force_lyrics`, `force_cue`, `force_tracklist`, `force_reencode_flac`, `force_reencode_images`, `force_audit`, `force_accurip`, `force_dr_replaygain`, `force_audiometa`, `force_mood`, `force_auto_tag`, `force_xlit`, `force_publish`, …) really turn a switch off, and script 20 is the one key that turns work *off* (`layout_apply`). Pure no-ops are skipped: `dr_replaygain_enabled` (7), `audiometa_enabled` (12), `mood_enabled` (16), `lyrics_xlit_enabled` / `lyrics_translate_enabled` (17), `lrclib_auto_publish` (18), `acoustid_enabled` (21, 22). By default cover art is **not** embedded (covers live on disk as `cover.*` plus per-track sidecars); Settings → *Embedded covers* (`embed_covers`, `embed_cover_jpeg_quality`, `embed_cover_resolution`) makes script 10 embed them.
### Grading
**70 checks** across tracks, albums, artist folders and folders, every key shipping ON; each toggleable on the **Grading** page with the **Strict / Balanced / Relaxed** presets; an album passes only when every enabled check passes. `grade_check_lossless_source` stands down when `library_codec` is uncompressed (`wav`/`aiff`) or `keep`, and `grade_check_cd_format` applies where a CD is expected. A tag **value** has one canonical form (`mlo/tagtext.py`), applied on every write and by script 10 library-wide: `RELEASECOUNTRY` holds every country the release states, earliest first, genres are stored broad-first (`Rock / Shoegaze / Dream Pop`), and a tag with more than one answer is a LIST of repeated container fields.
- **What is already in the file is graded too**: a `COMMENT` that carries anything fails (script 10 clears it, gated by `strip_unknown_tags`), every non-video track needs the `ACOUSTID_ID` + `ACOUSTID_FINGERPRINT` pair — `grade_check_acoustid` requires it with or without an API key, because script 21 creates the pair locally with `fpcalc` and only *submitting* needs `acoustid_user_key` — and a title written in a non-Latin script fails without an alias (`grade_check_alias_needed`). An album the import pipeline is still working on is left out of the verdict instead of counted as failing.
- Home and the Library open with the verdict and what fails: one row per album or track, capped at 12 with the rest a `+N` link into the *Failing* filter. Every check id, what it asserts, its default, the presets, the audit workflow, tag families and a runbook: [`docs/OPTIMIZATION-GRADING-SPEC.md`](docs/OPTIMIZATION-GRADING-SPEC.md).
### Export, playlists, offline
**Export** writes a playlist, albums, artists, tracks or the whole library as MP3 (VBR/CBR or custom), AAC, Opus, Vorbis, WAV, AIFF, ALAC, WavPack, WMA or a bit-exact `copy`, in the shipped `albumartist_album_disc` layout, or `flat`, `mirror` or a structure you type in Picard-style grammar (`export_codec`, `export_structure`, `export_subfolder`).
- `export_target` is `zip` (one archive the client downloads) or `server`, a folder picked with the drive list; `export_copy_files` names what is copied (tracks, covers, `.lrc`, `.cue`, `.log`/`.accurip`, `description.txt`, checksums, playlists). `export_manifest` writes `checksums.sha256`; `export_playlists` writes an `.m3u8` per album plus `all.m3u8`; sync mode (`export_prune`) removes audio the source no longer has; `export_replaygain_mode` is `off`, `tags` or `apply`, and `export_eq_profile` applies an imported Equalizer APO / Peace / AutoEq curve to the exported copies only.
- **Playlists** are manual (drag-reorder, favourites, `.m3u8` import/export) or smart (saved grade/audit/tag filters); **offline**, "Download" caches a track in the service worker's media cache, so a downloaded album plays with the server down (`download_codec` ships as **`copy`**, `playback_source` as **`stream`**).
### Notifications and languages
The backend publishes every settled outcome on `/ws/events` (`wish_found`, `wish_failed`, `wish_not_found`, `download_started`, `download_done`, `upload_started`, `import_needs_data`, …) and every client raises an OS notification from that socket; only a finished download and the end of a whole import are worth waking a device for (a started transfer, one album of a bulk run and a chain still running stay in the app), and the kinds are switchable per client (`notify_wish_found`, `notify_download_done`, …). **Remote push too**: the server signs with VAPID, encrypts each message (RFC 8291 `aes128gcm`) and keeps one row per subscribed device. The UI ships in six languages — English, Español, Français, Deutsch, 日本語, Português (Brasil) — chosen per browser (`localStorage: mlo.locale`), then the server's `ui_locale`.
## Clients
The same React build runs in every target, and **every one is a client of a server you run**: the Docker container on `127.0.0.1:8000`, a machine on the LAN, or a Tailscale name.

| Target | Built by | Artifact | What it is |
| --- | --- | --- | --- |
| Browser | the server (`web/dist`) | — | the app itself, over HTTP/S |
| Windows / macOS / Linux | `npx tauri build` | `.msi` + NSIS `.exe`, `.app` + `.dmg`, `.deb` + `.AppImage` | client of a server you run |
| Android | `npx tauri android build --apk --debug` | debug-signed APK | client of a server you run |
| iOS | `npx tauri ios build --target aarch64 --no-sign` | unsigned IPA | client of a server you run |

The iOS IPA ships as a **SideStore/AltStore source** — add `https://github.com/dillydalli3r/la-musica/releases/latest/download/source.json` once (`tools/make_sidestore_source.py` builds it, `.github/workflows/release.yml` publishes it). Both halves build locally — `cd web && npm install && npm run build`, then `cd ../desktop && npm install && npx tauri build` (`.github/workflows/desktop.yml` builds the three desktop bundles).
- **Desktop** is a shell and opens **its own wizard** (Server → Account → Notifications → Done), where *Test* probes `${address}/api/health`. **Capabilities are the server's** (`GET /api/capabilities`), both mobile artifacts are **sideload builds, signed by nobody here** (debug APK, `--no-sign` IPA), a plain-http server needs the platform's exemption (`desktop/src-tauri/Info.plist`, which also sets `UIBackgroundModes: audio` ; `.github/workflows/mobile.yml` enforces it).
## Terminal entry point
`python -m mlo` — the classic console menu: scripts 1–22, Run All, the config editor and the tool table. It is **not** stdlib-only (`mlo` imports `mutagen`), so run it from the server's environment.
## Security & accounts
Everything the API can do — read the library, rewrite tags, move and delete files, start downloads — is one password away from anyone who can reach the port; the top bar's rightmost control is the account menu (change password, sign out everywhere).

| Key | Default | What it does |
| --- | --- | --- |
| `auth_mode` | `auto` | `auto` = gate ON when `server_host` is not loopback; `required` = always; `off` = loopback only |
| `server_host` | `127.0.0.1` | where the server binds — and the address the gate reads |
| `server_port` | `8000` | the port |
| `auth_username` | `""` | the name shown on the login screen |
| `auth_password_hash` | `""` | PBKDF2-HMAC-SHA256, `pbkdf2$<rounds>$<salt-hex>$<hash-hex>` |
| `auth_session_days` | `30` | how long a session stays valid |
| `server_public_url` | `""` | the address clients should dial when it is not the page's own origin |

`auto` follows the bind: loopback (`127.0.0.1`, `::1`, `localhost`) keeps a single-user install password-free and anything else asks for a login — **from clients**, per request from the peer address; `X-Forwarded-For` is never trusted, and `off` on a non-loopback bind is treated as `required`.
- **A login**: PBKDF2-HMAC-SHA256, 600 000 rounds, random salt, constant-time comparison, minimum 8 characters, and a `users` table in `auth.db`; five consecutive failures make an address wait 30 s, doubling to 15 minutes. **Sessions** are 32-byte tokens and only their SHA-256 is stored, in `<music>/.mlo/data/auth.db`; the token travels as `Authorization: Bearer`, as the HttpOnly `mlo_session` cookie, or as `?token=` for the WebSockets (which close with code **4401** when it expires). `/api/auth/setup` and the static shell answer while `428` (`{"needs_setup": true}`) is in force until `POST /api/auth/setup` sets the password, and a **first run over the network** starts bound to the address you will use (`server_host: 0.0.0.0` or `MLO_SERVER_HOST=0.0.0.0`).
### The honest limits
- **One password, one user** (no roles, no permissions, no signup), and **the app does not terminate TLS**: put it behind a reverse proxy or a mesh VPN off-LAN and set `server_public_url`; the gate follows the configured `server_host`, not the socket. A browser with the push switch on is woken by the server's own Web Push, while the desktop and mobile shells notify only while they run; CUETools and AudioAuditor run on the image's mono runtime and Logchecker on its `php-cli`.
- **An archive inside an archive is not unpacked**, and **`.7z` and `.rar` need 7-Zip on the server**. **Submitting AcoustIDs needs a user API key** (`acoustid_user_key`; the read side needs only the client key), so script 22 is opt-in. **A podcast is a MusicBrainz series, not a release-group type**; **a drop on a phone can only send what the phone holds**.
## Architecture
`web/` React 19 + TypeScript + Tailwind UI (Vite, the service-worker media cache, six locales in `src/locales`) · `server/` FastAPI backend: library payload, playlists, import + the script chain, discovery, streaming, export, `/ws/events`, the sequential import runner (`import_queue`) and the login gate (`auth` + `api_auth`) · `mlo/` core engine (imports `mutagen`): grader, audit, lyrics, images, remux, naming, genres, acoustid, loudness · `desktop/` Tauri v2 shell · `tools/` test suites, the contract in `docs/`.
Everything the app fetches is stored under `<music>/.mlo/`: `data/config.json`, `data/playlists.db` (playlists, likes, favourites), `data/auth.db` (sessions and users — the token's SHA-256), `data/artwork.json`, `data/metadata_review.json`, `data/replaygain.json`, `data/audit_evidence.json`, `data/rym_cache/`, `data/lyrics_ai_cache/`, `data/wishes.db`, `data/update_check.json`, `downloads/`, `trash/<user>/`, `Artists/<Artist>/artist.jpg`, `<album>/description.txt`, `<album>/.mlo_expected.json`.
